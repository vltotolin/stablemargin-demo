# StableMargin

**Анализ ценовых рисков закупок для малого и среднего бизнеса.**

StableMargin связывает параметры будущей закупки с возможным изменением себестоимости, прибылью партии и потребностью в денежных средствах. Пользователь сравнивает варианты частичного хеджирования, проверяет сценарии расхождения закупочных и биржевых цен и формирует карточку для финансового специалиста.

**[Открыть приложение](https://vltotolin.github.io/stablemargin-demo/)**

## Что доступно

| Раздел | Возможности |
|---|---|
| Оценка закупки | Стоимость партии, минимальная прибыль, денежный резерв, допустимый объём контракта |
| Варианты позиции | Без защиты, минимальный объём по выбранному сценарию, максимум по резерву, номинальное покрытие |
| Стресс-тест | Пять сценариев цен и матрица чувствительности 5 × 5 |
| Товар и валюта | Разложение изменения рублёвой стоимости кофе на сырьевой и валютный факторы |
| Список закупок | Несколько расчётов в пределах открытой вкладки, выгрузка CSV |
| Карточка для специалиста | Параметры закупки, ограничения, сценарные результаты, экспорт HTML и JSON |

**Демонстрация:** откройте приложение, выберите «Какао» и нажмите «Обзор возможностей». Пример с ужесточением порога прибыли показывает ограничение по денежному резерву; пример без подтверждённой связи цен блокирует подбор позиции.

## Техническая часть

Статическое веб-приложение на HTML, CSS и JavaScript. Сервер, установка зависимостей и регистрация для просмотра не требуются. Для локального запуска откройте `index.html`. GitHub Pages использует ветку `main` и корень репозитория.

- `index.html` — структура интерфейса;
- `styles.css` — оформление;
- `app.js` — события интерфейса, отчёты и выгрузки;
- `core.js` — независимое расчётное ядро;
- `core.test.js` — автоматические тесты;
- `README.md` — описание проекта.

Запуск тестов при наличии Node.js: `node --test core.test.js`. Расчётное ядро проходит 42 автоматических теста, включая параметризованные проверки финансовых ограничений.

## Текущий статус

Прототип выполняет **сценарный расчёт**, а не прогноз рыночной динамики. Изменения цен и параметры контракта вводятся вручную. Подтверждение документа закупки, ценовой связи, актуальности котировки и ликвидности пока выполняется пользователем через переключатели, а не автоматически. Биржевые сделки, банковские интеграции и бухгалтерский учёт не подключены.

Для следующего этапа предусмотрены проверка реальных прайсов поставщиков, загрузка актуальных данных биржи и клиринга, оценка исторического базисного риска и испытания с предприятиями.
